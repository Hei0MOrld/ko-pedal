# 自作ベース用スマートペダル — 完成品の仕様(2026-09-30)

## 10/1 統合版のまとめ(Windows 側 + MacBook 側の検討)

MacBook の Claude との検討(10/1 にメール「ペダル企画」で受け取り)を、この仕様書と合わせた。

### 両方で一致していること(決定)
- 音は有線。Bluetooth・USB・Wi-Fi は操作と編集だけ
- ラズパイ単体で鳴る。PC・スマホは音作りと編集のときだけ
- ベース(ギター)を直接挿せる Hi-Z 入力
- NAM を使う。比べる相手は Darkglass Anagram
- 本体はフットスイッチ3つ。強みは増設箱をいくつでも足せること
- 土台のソフトは PiPedal(Mac 側の「案B」と同じ)。ラズパイは Pi 5(4GB)が有力
- 増設箱は小さなマイコン(RP2040 = Raspberry Pi Pico と同じチップ)+ USB-MIDI
- 起動中・故障時はリレーで音を素通り。音色を切り替えても途切れない

### MacBook 側から新しく加わったこと
- **本体にボリュームのつまみ**を1つ付ける
- **方向性**: まず自分用に作り切る。製作過程を英語で発信する。完成品の販売はしない。増設箱だけを売る案も見送り
- **増設箱の番号は箱ごとの ID**(マイコンに書き込む)。並び順で決めると、並べ替えたときに割り当てがずれて本番で事故になるため
- **増設箱のつなぎ方の発展**: 第2段階で箱の中に USB ハブを入れて数珠つなぎ(最大5段)。ステージ用なら頑丈な LAN ケーブル(etherCON)と CAN 通信
- **起動は15秒以内を目標**
- **案C**: 自作の拡張ボード(KiCad で設計 → JLCPCB に発注、約2〜3千円+部品代)
- **採用候補**: スイッチごとのフルカラー LED リング(役割で色を変える)、ケースに「琥」ブランドのレリック加工やオイル仕上げ
- **発信の企画**: ハードオフのジャンク機材(ペダルやベース用プリアンプ)の音を NAM で取り込んで無料配布。ジャンクを直して売る動画と素材を共有できる。反応が出たら予約金で需要を確かめる(無料の事前登録の件数は当てにしない)

### MacBook 側で検討してやめたこと
- 増設箱を磁石とポゴピンでパズル状につなぐ方式(踏まれる・蹴られると接触不良、飲み物で腐食)
- 増設箱の番号を並び順で決める方式(上記)
- 専用 OS の自作(数か月かかり、元のソフトの更新に追いつけない)

### 食い違いの決着(10/1 KO が決定)
1. **ベース向け**(KO がベーシストだから)。Mac 側の「ギター寄り」はやめる
2. **AI と話してエフェクトを作る機能は入れる**(目玉機能のまま)
3. **まず自分で使う → SNS に投稿 → 使いたい人が出てきたら、そのとき売ることも考える**。最初から販売は目指さない(Mac 側の「販売しない」と、反応が出たら予約金で需要確認、をこの順番でつなぐ)
4. **ライブでも使う**。そのため次が必須になる:
   - XLR の DI アウト + グラウンドリフト
   - 起動中・故障時のリレーで素通り、起動は15秒以内が目標
   - 頑丈なジャック・端子。増設箱をステージで使うときは、頑丈な LAN ケーブル(etherCON)と CAN 通信を検討
   - ペダルの上で今の音色がわかること(画面か LED リング。Wi-Fi がなくてもペダルだけで全部できる)
5. **ペダルの画面**: 10/2 に決定(下の「本体と増設箱の操作部」)

### 本体と増設箱の操作部(10/2 決定)
- **本体のフットスイッチは5つ**: エフェクターを割り当てる 1 / 2 / 3(10/3 に A / B / C から改名。長押しで組み合わせの呼び出し。下の「ボタンの動き」)+ 固定の **TUNER**(踏むと音が消えてチューナー)+ 固定の **BYPASS**(ペダル全体を素通り)。**横一列**に並べる(左から TUNER・1・2・3・BYPASS)。2段は踏みにくいのでやめた(10/2 KO)。間隔は 65mm
  - 大きさの目安: 幅 330mm × 奥行き 120mm × 高さ 奥 65mm / 手前 45mm(くさび形。奥にラズパイと音の基板、手前はスイッチの裏だけ)。平らな箱なら高さ 約 60mm。増設箱は 約 200 × 110mm
  - BYPASS はリレーを動かす。ラズパイが固まっても足で素通りに戻せるようにする
  - タップテンポは固定ボタンにせず、A / B / C や増設箱に割り当てて使う
- **表示**: スイッチごとの **LED リング**(WS2812B、役割で色を変える)+ **2.0〜2.4インチのカラー液晶**(ST7789 など)で音色の名前。足元 1.2〜1.5m から読むには文字の高さ 8〜10mm 必要 → 0.96 / 1.3インチ OLED は小さすぎる。Huawei スマホ案は見送り
- **スイッチと LED は Pi Pico に任せる**(本体の中に増設箱が1台入っている形。Pi 5 では WS2812 の定番ライブラリがそのまま動かないため)。LED は 5V、ラズパイの 3.3V 回路と混ぜない
- **フットスイッチの部品はモーメンタリ**(踏んでいる間だけ ON)。使うときの動きは「1回押すと ON のまま」だが、状態は Pico とソフトが覚える。理由: 音色ごとに ON / OFF を覚えるのでラッチ式だとずれる、長押しが測れない
- **増設箱はボタン3つ**(本体の A / B / C とそろえる)、LED リング付き。1台あたり約3,600〜6,500円(LED を1個ずつにすれば約2,600〜4,700円)。数珠つなぎ用の USB ハブを入れると +500〜1,000円
- **背面に足すもの**: ロック付きの DC ジャック(抜けにくい)、**DI の PRE / POST 切り替え**(PA に送る音を、エフェクト前のきれいな音か、エフェクト後の音か選ぶ。KO はアンプをあまり持って行かないので、普段は POST)
- 余裕があれば: microSD を外から抜ける穴、AUX IN + ヘッドホン(次に入れる機能)

### 仮決め(10/2。部品がそろってから、やりながら変えてよい)
1. **OS**: Raspberry Pi OS Lite(64bit、**Bookworm** = Imager の「Legacy, 64-bit Lite」)。起動が速く、音に CPU を回せる。**10/3 訂正**: PiPedal 公式が対応と書いているのは Bookworm だけ(Trixie の記載なし)なので、Trixie はやめた。手順は DAY1_SETUP.md。SD への書き込みは PC + カードリーダーで、Wi-Fi などの設定もそのとき済ませる
2. **Pico のプログラム**: CircuitPython。USB-MIDI が最初から使え、ファイルを保存するだけで書き換えられる。速さはボタンと LED には十分
3. **LED の色**: 琥珀色 = 今の音色 / 青 = ON 中のエフェクト / 消灯 = 使っていない / 赤 = TUNER 中 / 白 = BYPASS 中。明るさは 20〜30%
4. **増設箱のつなぎ方**: まず USB。ライブで困ったら etherCON + CAN
5. **最初に作る音色3つ**(A / B / C に割り当てる): A = クリーン(コンプ + EQ)/ B = 歪み(NAM: SansAmp か B7K 系 + キャビの響き)/ C = 飛び道具(オクターバーかエンベロープフィルター)。届いた日の負荷の実験の材料にもする
6. **試す NAM**(TONE3000、ベース用): Darkglass B7K(キャビ込み)/ Ampeg SVT-CL / SansAmp Bass Driver を含むパック / ベースのペダルボード一式 / メタル系ベースパック。標準サイズと軽いサイズ(A2・lite)があれば両方入れて、負荷を比べる

## 目指す方向(9/30 決定)

**「普通のマルチエフェクターとして既製品に勝つ」は目指さない。「既製品ではできないことができる、自分のペダル」を目指す。**

- **普通の音は既製品並みにする**: アンプ・歪みのリアルな音は NAM(ベース専用の高級機 Darkglass Anagram も中で使っている)、それ以外は定番のエフェクト(PiPedal / MOD に入っているもの)を使う
- **売り(ここで勝負する)**:
  1. **AI と話して、自分だけのエフェクトを作れる**(9/30 に PC で、トレモロ・歪み・こだま・ワウが実際に鳴るところまで確認済み)
  2. **ボタンを後からいくらでも足せる**(Anagram でも弱点になっている)
  3. スマホのブラウザで、アプリなしで編集できる
  4. 中身を全部、自分で好きに変えられる
- **既製品に負けると認めているところ**: エフェクト1つ1つの磨き込み(Boss・Line 6 はプロが何年もかけて調整している)、雑音の少なさ、丈夫さ・安心感(起動の遅さ、電源をいきなり抜くと壊れることがある)、値段(部品代だけで Zoom B6 くらい)
- **AI に作らせる分担**: リアルなアンプや歪みは NAM に任せる(9/30 に AI が作った単純な歪みは、ヘッドホンでは「安っぽい」だった)。AI には「既製品にない変わったエフェクト」を作らせる

## ボタンの動き(10/3 決定。押して試せるページ: button_sim.html)

**スイッチ1つ = エフェクター1台。** 本体の 1 / 2 / 3 と増設箱のスイッチは全部同じ扱いで、箱を足すほどエフェクターが増える。両端の TUNER と BYPASS だけ役割が固定。
(10/2 までの「ボタンごとに音色 / ON・OFF を選ぶ」案と、10/3 に検討した「本体 A/B/C = 音色、増設箱 = 音色ごとに中身が変わる」案はやめた。足で覚えられること、並びが変わらず音が途切れにくいことを取った。2回のプロの目線のチェック(AI が立場を想定)を通した)

| 操作 | 何が起きるか |
|---|---|
| どのスイッチでも短く押す | 割り当てたエフェクトが ON / OFF する |
| 本体の 1 / 2 / 3 を長押し(初期 0.6秒) | 覚えておいた ON / OFF の組み合わせ(3つ)に切り替わる。最初は3つとも空き |
| TUNER | 音を消してチューナー。TUNER 中はどのスイッチを踏んでも抜ける |
| BYPASS | リレーで直結。ラズパイが固まっても効く |

決まりごと:
1. どのスイッチにどのエフェクトを割り当てるかは、スマホで自由に決める。スイッチの中身は組み合わせによって変わらない
2. 音の順番(エフェクトの並び)はスマホで決め、スイッチの場所とは関係ない。並びは常に同じで、変わるのは ON / OFF だけ
3. **本体の 1 / 2 / 3 だけ**、短押しの ON / OFF は足を離したときに切り替える(長押しと見分けるため)。増設箱・TUNER・BYPASS は踏んだ瞬間に切り替える(遅れなし)
4. 長押しは、しきい値になった瞬間に組み合わせを呼び出し、離したときは何もしない。呼び出せたら LED を1回光らせる。しきい値は 0.5〜1.0秒でスマホから変えられる。チャタリング除けは 20〜30ms
5. 空きの組み合わせを長押ししたら何も変えず、液晶に「空き」と出す。組み合わせの中身はスマホで覚えさせる
6. 組み合わせは、増設箱も含めた全部のスイッチの ON / OFF を覚える。つないでいない増設箱の分も消さずに持っておく。覚えた組み合わせから変えたら、液晶の名前に「*」
7. OFF のエフェクトも読み込んだままにして素通りさせる(負荷がいつも「全部 ON」と同じになり、本番で急に重くならない)。切り替えは 10〜20ms でなめらかにつなぐ。割り当てるときに全部 ON の負荷を確かめ、超えたら断る(目安 70%。実測で決める)
8. エフェクトごとに出力の音量を持たせる。NAM は入れるときに音量をそろえる(NAM は機種ごとに音の大きさがかなり違い、2段重ねの片方を外すと音量が落ちるため)。「エフェクトはわかりやすく大きめ」は家で試すときだけで、ライブ用の設定とは分ける
9. 増設箱のケーブルが抜けても音は止めない。ON / OFF を保ったまま液晶に「増設箱 2 抜け」と出し、差し直したら LED を今の状態に合わせる
10. 液晶の下の段に、スイッチの並びどおりにエフェクトの名前を出す(青い LED だけでは何のスイッチか分からない)。増設箱にはテープで名前を貼る
11. 電源を入れたら、前回の ON / OFF に戻す
12. 出力の最後の音量の上限(リミッター)は、どのスイッチでも外せない

あとで足す機能:
- スイッチごとに「踏んでいる間だけ ON」にする設定
- 足だけで今の状態を組み合わせに上書きする操作(例: TUNER と 1 を同時に長押し)
- ディレイやリバーブを切ったときに、残響が自然に消えていく(テール)

### エクスプレッションペダル(EXP 端子)

- ワウ・ボリューム・オクターバーの混ぜる量などを、踏み込み具合でなめらかに動かす。何を動かすかはスマホで割り当て、長押しの組み合わせごとに変えられる(KO 10/3: オクターバーをちょっとだけ使うのも、フットスイッチより EXP で量を動かす方がいい)
- 買うのはワウそのものではなくエクスプレッションペダル(Roland EV-5、M-Audio EX-P など、数千円。中身は可変抵抗1つなのでジャンクでも可)。TRS ケーブルでつなぐ
- メーカーで配線の向きが違うので、端子の横に切り替えスイッチを付ける
- Pico で読める端子は3つで、VOLUME のつまみが1つ使う → EXP は最大2台

## 目玉機能: AI と話してエフェクトを作る(9/30 追加)

スマホで AI と会話しながら、音を作って、ペダルに入れて、保存できる。誰でも使える(プログラムを書けなくていい)。

| 段階 | 何をするか | 速さ | 例 |
|---|---|---|---|
| レベル1 | AI が、入っているエフェクトの組み合わせとつまみを決める | その場で鳴る | 「80年代ファンクの、太くてパキッとしたベースにして」 |
| レベル2 | AI が、新しいエフェクトを Faust で書く → LV2 に変換 → ペダルに入れる | 数十秒〜1分 | 「1オクターブ下を少し遅れて重ねるエフェクトを作って」 |

- 気に入ったら名前を付けて保存。レベル2で作ったエフェクトは、ボタンにも割り当てられる
- **必須の安全装置**: 出力の最後に、音量の上限(リミッター)を必ずかける。AI が書いたエフェクトの間違いで爆音が出ても、耳とスピーカーを守る
- AI はペダルの中では動かないので、ネットが必要。音作りは家でして、ライブでは保存した音を使う
- 似た既製品(ToneCraft、Spark AI、Fukkaudio)はレベル1のみで、ほぼギター向け。ベース向け・自作ペダルで動く・レベル2まで、というものは見当たらない
- Faust は AI と相性がいい(公式説明書に「LLM で書く」章がある)。単純な効果(トレモロ、変わった歪み、ディレイ)は得意。本物のアンプのような複雑な音は苦手

### 試作のやり方とつまずいたところ(9/30 に実際にやってわかったこと)

- 作ったもの: `faust/tremolo.dsp`(トレモロ)、`faust/drive.dsp`(ベース用の歪み。KO が弾いて「ザラザラしてる」= 成功)
- Chrome の自動翻訳を切る。オンだとコードの `process` が「プロセス」に訳されて動かない
- Faust IDE のサイトに**マイクを許可**する(アドレスバー左のアイコン)。これがないとベースの音が入らない
- Windows の音の出力先を **UR12** にする。配信のスクリプトが Beoplay H95 にしているので、そのままだとブラウザの音が UR12 のヘッドホンに来ない。`game_stream_auto/set_default_audio.ps1 -Match "UR12"` で切り替えられる(配信を始めると自動で H95 に戻る)
- 入力は `bass = +;`(UR12 の入力1と2を足す)にする。ブラウザが入力を1本にまとめて受け取ることがあり、`!, _`(入力2だけ)だと何も入らなかった
- UR12 は弾いた音をそのまま返す(止めるスイッチはないはず)。ブラウザの音は数十 ms 遅れるので、**元の音とずれて「ディレイみたい」に聞こえる**。トレモロは揺れが薄まる。音を伸ばして聞くとわかりやすい。完成品(数 ms)では起きない
  - **10/6 訂正**: UR12 の前面に DIRECT MONITOR の押しボタンがあり、OFF にすると素の音は返らない(PiPedal を止めて無音になるのを KO が確認)。押し込みの向きは見た目で分かりにくいので、音で確かめる

## このペダルの強み(既製品との違い)

ベース用マルチの既製品(Zoom B6、Boss GT-1B、Line 6 HX Stomp、Darkglass Anagram など)に対して:
- ボタンを後からいくつでも足せる
- アプリなしで、ブラウザから編集できる
- 中身を自分で好きに変えられる

部品代だけで既製品と同じくらいになるので、値段では勝てない。自分用として作る前提。

## 調べてわかったこと(9/30、Web 検索)

- **実際のベーシストの不満(TalkBass)**: 一番多いのは「音色ごとに音量がバラバラ」。次が「音色の切り替えで音が一瞬途切れる」(アンプの型を変えるときに出やすい。エフェクトの ON/OFF だけなら途切れない)、「オクターバーが低い弦でうまく追従しない」
- **Darkglass Anagram**(ベース専用の高級機)の弱点: 外部フットスイッチやエクスプレッションペダルを MIDI なしでつなげない。電源スイッチがない → **ボタンを後から足せる、はこのペダルの本当の強みになる**
- **pi-Stomp**(ラズパイ+MOD の自作キット): 遅延 2.67ms(96kHz・128)〜5.33ms(48kHz)。部品約 $198。画面と、Arduino からの USB-MIDI でボタンをつないでいる → 増設ボックスも USB-MIDI 方式でいける
- **PiPedal**(ラズパイ用のエフェクターソフト、無料): Pi 4/5 対応。**スマホのブラウザで操作、Wi-Fi がなければ自分でホットスポットを出す**、NAM 対応、MIDI のフットスイッチ対応 → この構想にいちばん近い。MOD の代わりの土台候補
- **Pisound**: Pi 5 対応(v1.2 から)。入力のゲインは 0〜+40dB。ただしベースを直接挿すなら、前に Hi-Z バッファがあった方がいい

## 土台のソフト(9/30 決定)

**第一候補: PiPedal / 予備: MOD**

- PiPedal にした理由: スマホで編集する前提で作られている。Wi-Fi がなければ自分でホットスポットを出す。NAM が最初から入っている。この3つが構想の中心と一致する
- MOD の弱点: 編集画面が PC 向け(ドラッグで並べる)で、スマホだと使いにくい。あとから直すのが大変
- PiPedal の気になるところ: ハード(箱・ボタン・画面)の見本がない → pi-Stomp の作りを参考にする。ボタンの割り当てがどこまで細かくできるかは未確認
- どちらを選んでも自分で作る部分: ボタンごとの「音色 / ON・OFF」の切り替え、ペダルの画面に音色の名前を出すところ
- 試し方: 同じラズパイで SD カードを差し替えるだけで両方試せる。まず PiPedal でスマホから音を作ってベースを弾く。使いにくければ MOD を試す
